TP-5: Evaluasi Kelayakan Rancangan Pseudocode Sebelum Pengodean

Gunakan 5 indikator kualitas rancangan untuk menilai kelayakan rancangan kelompok pasangan sebelum ditranslasikan ke bahasa pemrograman.

Indikator Kelayakan Rancangan Status Catatan & Rekomendasi Perbaikan
1. Kelengkapan Struktur Blok
Memuat bagian Header, Deklarasi, dan Deskripsi (MULAI–SELESAI) secara lengkap.
2. Kejelasan Tipe Data
Seluruh variabel yang dipakai di bagian Deskripsi sudah dideklarasikan dengan tipe data yang tepat.
3. Ketunggalan Makna (Tidak Ambigu)
Setiap baris memuat satu instruksi tunggal dengan kata kunci standar (bukan kalimat cerita bebas).
4. Ketepatan Struktur Kontrol
Blok percabangan IF-THEN-ELSE memiliki syarat kondisi yang jelas dan ditutup dengan ENDIF.
5. Kesiapan Translasi
Rancangan dapat diterjemahkan baris demi baris ke bahasa pemrograman nyata tanpa menimbulkan kebingungan sintaksis.

Bagian 2: Capaian dan Tujuan Pembelajaran

Capaian Pembelajaran yang Relevan Tujuan Pembelajaran Bukti Ketercapaian yang Diharapkan
Elemen Algoritma dan Pemrograman (Fase E):
"Pada akhir fase E, peserta didik mampu memahami alur logika penyelesaian masalah, merancang algoritma menggunakan notasi algoritmik (pseudocode) yang terstruktur, serta menganalisis dan mengevaluasi rancangan tersebut sebelum ditranslasikan ke dalam sintaks bahasa pemrograman komputer." 		TP-1 (C1): Peserta didik mampu mengidentifikasi struktur dasar (header, deklarasi, deskripsi), tipe data, operator, dan kata kunci (keywords) standar dalam penulisan pseudocode. Lembar hasil identifikasi dan pelabelan bagian header, variabel beserta tipe datanya, operator, dan kata kunci pada contoh teks pseudocode yang diberikan.
TP-2 (C2): Peserta didik mampu menjelaskan alur logika penyelesaian suatu masalah kontekstual dengan menguraikan komponen masukan (input), proses, dan keluaran (output) secara runtut. Tabel pemetaan Input–Proses–Output (IPO) serta uraian langkah logika terurut dari studi kasus masalah kontekstual.
TP-3 (C3): Peserta didik mampu menuliskan rancangan algoritma penyelesaian masalah sederhana ke dalam format pseudocode terstruktur yang memuat operasi sekuensial dan struktur kontrol percabangan (IF-THEN-ELSE). Draf rancangan pseudocode lengkap (memuat header, deklarasi variabel/tipe data, serta blok deskripsi input, percabangan IF-THEN-ELSE, dan output) sesuai kaidah penulisan standar.
TP-4 (C4): Peserta didik mampu menganalisis kebenaran alur logika dan mendeteksi kesalahan urutan instruksi (logical error) pada rancangan pseudocode menggunakan teknik penelusuran manual (dry-run). Tabel penelusuran (trace table) yang terisi akurat baris demi baris berdasarkan skenario data uji beserta catatan hasil deteksi atau perbaikan kesalahan logika.
TP-5 (C5): Peserta didik mampu mengevaluasi kelayakan rancangan pseudocode berdasarkan kriteria keterbacaan (readability), ketunggalan makna (tidak ambigu), dan kelengkapan strukturnya sebelum ditranslasikan ke bahasa pemrograman. Lembar tinjauan (review) kelayakan pseudocode berbasis indikator (kejelasan tipe data, ketepatan struktur blok, dan bebas ambiguitas) disertai kesimpulan serta rekomendasi perbaikan rancangan.

Bagian 3: Materi Pembelajaran

Tujuan Pembelajaran Materi Esensial Materi Prasyarat Kedalaman / Ruang Lingkup
TP-1 (C1) Anatomi dan struktur baku pseudocode (Bagian Header, Deklarasi, Deskripsi), jenis tipe data dasar (Integer, Real, String, Boolean), operator, serta kata kunci (keywords) standar (MULAI, SELESAI, INPUT, OUTPUT, SET/←). Konsep dasar Berpikir Komputasional (Computational Thinking: dekomposisi, abstraksi, dan algoritma) serta penyusunan urutan langkah logis sehari-hari. Pengenalan fungsi masing-masing blok struktur, pembedaan tipe data primitif sesuai jenis nilai variabel, serta konvensi penulisan operator aritmetika/relasional dan kata kunci dasar secara independen (tidak terikat sintaks bahasa tertentu).
TP-2 (C2) Pemetaan masalah komputasional menggunakan kerangka Input–Proses–Output (IPO) serta penyusunan alur logika sekuensial dan keputusan sederhana. Pemahaman struktur dasar, variabel, tipe data, dan kata kunci standar pseudocode (TP-1). Dekomposisi studi kasus kontekstual untuk mengidentifikasi variabel masukan, merumuskan aturan pengolahan logika kondisi, dan menentukan keluaran secara runtut serta bebas ambiguitas sebelum dituangkan ke notasi formal.
TP-3 (C3) Penulisan notasi algoritmik pseudocode terstruktur untuk operasi sekuensial dan struktur kontrol percabangan (IF-THEN dan IF-THEN-ELSE). Kemampuan memetakan masalah ke dalam komponen IPO dan alur logika runtut (TP-2). Penyusunan pseudocode lengkap (memuat Header, Deklarasi, dan Deskripsi) untuk kalkulasi dan pengambilan keputusan dua arah (IF-THEN-ELSE), dibatasi pada percabangan dasar tanpa perulangan agar realistis bagi pemula dalam alokasi waktu 180 menit.
TP-4 (C4) Teknik simulasi eksekusi manual (dry-run), penyusunan trace table, serta identifikasi kesalahan logika (logical error / bug). Rancangan pseudocode terstruktur yang memuat operasi sekuensial dan percabangan IF-THEN-ELSE (TP-3). Pelacakan perubahan nilai setiap variabel baris demi baris menggunakan skenario data uji normal dan data batas (edge case) untuk memverifikasi ketepatan alur kondisi serta mendeteksi letak kesalahan urutan instruksi atau rumus.
TP-5 (C5) Kriteria kualitas rancangan pseudocode: keterbacaan (readability), ketunggalan makna (tidak ambigu), kelengkapan struktur blok, dan kesiapan translasi. Hasil analisis kebenaran logika dan trace table yang valid (TP-4). Penilaian kritis terhadap kelengkapan deklarasi tipe data, kejelasan penamaan variabel, keruntutan blok IF-THEN-ELSE ... ENDIF, dan sifat independen bahasa agar rancangan siap ditranslasikan ke bahasa pemrograman nyata tanpa multitafsir.

Lampiran 1: Bahan Ajar Ringkas Konvensi Penulisan Pseudocode

A. Pengertian dan Prinsip Dasar Pseudocode

Pseudocode (kode semu) adalah notasi deskriptif tingkat tinggi yang digunakan untuk merancang alur logika algoritma secara terstruktur menggunakan bahasa yang mudah dipahami manusia, namun mengikuti pola urutan instruksi komputasional. Pseudocode bersifat independen terhadap bahasa pemrograman (tidak terikat aturan sintaks khusus seperti titik koma pada C++ atau indentasi ketat pada Python) agar perancang dapat fokus menguji kebenaran logika sebelum proses pengodean (coding).

B. Anatomi Struktur Baku Pseudocode

Setiap rancangan pseudocode standar terdiri atas tiga bagian utama yang berurutan:

  1. Bagian Judul (Header): Menjelaskan nama algoritma secara singkat dan spesifik, diawali kata kunci PROGRAM atau ALGORITMA (penulisan nama menggunakan garis bawah _ tanpa spasi).
  2. Bagian Deklarasi (Declaration): Mendaftarkan seluruh nama variabel dan konstanta yang digunakan beserta tipe data primitifnya:
    • Integer : bilangan bulat (contoh: jumlah_barang, umur).
    • Real : bilangan desimal/pecahan (contoh: total_belanja, diskon, nilai).
    • String : kumpulan karakter/teks (contoh: nama_siswa, status).
    • Boolean : nilai logika kebenaran (True atau False).
  3. Bagian Deskripsi (Description): Berisi inti langkah-langkah eksekusi algoritma dari atas ke bawah yang diapit kata kunci MULAI dan SELESAI, menggunakan kata kunci standar berikut:
    • Masukan & Keluaran: INPUT <nama_variabel> dan OUTPUT <nilai_atau_variabel>.
    • Penugasan Nilai (Assignment): SET <variabel> ← <nilai_atau_ekspresi>.
    • Operator Aritmetika & Relasional: + (tambah), - (kurang), * (kali), / (bagi), = (sama dengan), != (tidak sama dengan), < (kurang dari), > (lebih dari), <= (kurang dari atau sama dengan), >= (lebih dari atau sama dengan).
    • Struktur Kontrol Percabangan:
    IF <kondisi_logika> THEN
    <instruksi_jika_kondisi_benar>
ELSE
    <instruksi_jika_kondisi_salah>
ENDIF

C. Contoh A — Pseudocode Valid (Bahan Identifikasi LKPD 1 Bag. A)

PROGRAM Penentuan_Kelulusan_Siswa
DEKLARASI:
    nilai_akhir : Real
    batas_lulus : Integer
    keterangan : String
DESKRIPSI:
MULAI
    SET batas_lulus ← 75
    INPUT nilai_akhir
    IF nilai_akhir >= batas_lulus THEN
        SET keterangan ← "Lulus"
    ELSE
        SET keterangan ← "Remedial"
    ENDIF
    OUTPUT keterangan
SELESAI

D. Contoh B — Pseudocode Beranotasi dengan Logical Error (Demonstrasi Dry-Run Pertemuan 2)

Tujuan Kasus: Sistem peringatan otomatis ruang server akan menampilkan "Peringatan: Suhu Panas" apabila suhu ruangan melebihi 30°C, dan menampilkan "Suhu Normal" apabila suhu 30°C atau kurang.

PROGRAM Cek_Suhu_Server
DEKLARASI:
    suhu : Real
    status : String
DESKRIPSI:
MULAI
    INPUT suhu
    IF suhu >= 30 THEN
        // [ANOTASI BUG]: Seharusnya operator '>', bukan '>='
        SET status ← "Peringatan: Suhu Panas"
    ELSE
        SET status ← "Suhu Normal"
    ENDIF
    OUTPUT status
SELESAI

Catatan Analisis: Pada data batas suhu = 30, kondisi suhu >= 30 bernilai True sehingga menghasilkan "Peringatan: Suhu Panas", padahal sesuai aturan kasus suhu tepat 30°C masih termasuk kategori normal.
